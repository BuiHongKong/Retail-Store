🔩 Component Breakdown

☁️

VPC & Networking Both Envs

Two isolated VPCs: 10.0.0.0/16 (staging) and 10.1.0.0/16 (prod). Each spans 2 Availability Zones with a public subnet for the ALB and private subnets for ECS tasks and RDS. A NAT Gateway is optional (flag-controlled) — when disabled, ECS tasks run in public subnets with a public IP for ECR pulls.

⚖️

Application Load Balancer Both Envs

A single internet-facing ALB sits in the public subnets. It uses path-based listener rules (priority-ordered): /api/admin* → Admin (p10), /api/cart* → Cart (p20), /api/checkout* → Checkout (p30), /api/orders* + /api/auth* → Auth (p40/50), /api* + /uploads* → Main (p60). Everything else hits the Frontend (default). Prod also routes /grafana to Grafana.

🚀

ECS Fargate — 6 Services Both Envs

All containers are serverless Fargate (no EC2 to manage). Each task is 256 CPU / 512 MB. Services: Frontend (Vite/Nginx :80), Main (:3000), Cart (:3001), Checkout (:3002), Auth (:3003), Admin (:3004). One shared backend image is distinguished at runtime by the SERVICE env variable via entrypoint.sh.

📈

ECS Auto-Scaling Prod Only

Application Auto Scaling with Target Tracking at CPU 70%. Scale-out cooldown: 60s. Scale-in cooldown: 180s.

Frontend, Main, Cart, Checkout: min 1, max 6
Auth, Admin: min 1, max 2 (lower traffic, cost-saving)

🗄️

RDS PostgreSQL 15 Both Envs

Managed db.t3.micro instance with 20 GB of storage. Database name: retail_store. Lives in the private subnets with a dedicated security group — only ECS tasks on port 5432 can connect. Schema is managed by Prisma; seed runs as a one-off ECS task via CI/CD.

📦

ECR Repositories Both Envs

Two private ECR repos per environment: retail-store-frontend-{env} and retail-store-backend-{env}. Images are tagged staging-{sha} / staging-latest or prod-{sha} / prod-latest. A lifecycle policy retains the last 10 images automatically. Prod also has a retail-store-grafana-prod repo for the custom Grafana image.

🗃️

S3 — Product Image Uploads Both Envs

One S3 bucket per environment for admin-uploaded product images. Configured with public read so image URLs work directly in browsers. The ECS task role has a least-privilege IAM policy allowing only PutObject and GetObject on this specific bucket.

📊

Observability — LGTM Stack Prod Only

Prometheus scrapes GET /metrics from all 5 backend services (ports 3000–3004) and Node Exporter sidecars (port 9100) for CPU/memory. Loki (loki.retail-store.local:3100) handles log aggregation. Grafana (custom ECR image with pre-provisioned dashboards) is exposed at ALB path /grafana. Service addresses are resolved via AWS Cloud Map private DNS namespace retail-store.local.

🔍

Cloud Map — Service Discovery Prod Only

Private DNS namespace retail-store.local is registered in the prod VPC. Each backend ECS service registers its IP, enabling Prometheus to resolve main.retail-store.local:3000, cart.retail-store.local:3001, etc. without hardcoded IPs. Prometheus and Loki themselves are also registered so Grafana can reach them.

🔒

Security Groups Both Envs

ALB SG: ingress HTTP :80 from 0.0.0.0/0.
ECS SG: ingress :80 and :3000–3004 from ALB SG only. In prod, also ingress :3000–3004 and :9100 from the Observability SG for Prometheus scraping.
RDS SG: ingress :5432 from ECS SG only. No public database access.

🔄

CI/CD Pipeline — GitHub Actions Both Envs

Push to main triggers: (1) lint frontend, (2) build Docker images with staging-{sha} and staging-latest tags, (3) push to ECR, (4) rolling update-service on all 6 ECS services, (5) one-shot Prisma seed task. Prod deploy is a separate job gated by a prod GitHub Environment approval. It tags the current prod-latest as prod-previous first (enabling 1-step rollback), then builds and deploys fresh images.

📝

CloudWatch Logs Both Envs

Every ECS task uses the awslogs log driver. A dedicated log group is created per service: /ecs/retail-store-{env}-frontend, /ecs/retail-store-{env}-main, etc. Retention is set to 7 days to prevent runaway costs. IAM execution role has AmazonECSTaskExecutionRolePolicy for ECR pull and CloudWatch write access.
